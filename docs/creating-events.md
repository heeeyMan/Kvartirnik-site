# Создание нового квартирника

## Быстрый старт (скрипт)

```bash
./scripts/new-event.sh
```

Скрипт задаст вопросы и автоматически создаст:
- Файл `content/kvartirniki/YYYY-MM-DD.md` с заполненным frontmatter
- Папку `static/images/kv_list/YYYY-MM-DD/` для фотографий
- Папку `static/images/kv_list/YYYY-MM-DD/thumbs/` для превью

Новый эвент создаётся с `draft: true`. Когда всё готово — поменяйте на `draft: false`.

---

## Ручное создание

### 1. Создайте файл контента

Путь: `content/kvartirniki/YYYY-MM-DD.md`

Имя файла — дата мероприятия в формате `YYYY-MM-DD`.

### 2. Создайте папки для фото

```
static/images/kv_list/YYYY-MM-DD/
static/images/kv_list/YYYY-MM-DD/thumbs/
```

### 3. Заполните frontmatter

## Структура frontmatter

```yaml
---
title: "Квартирник в Название Места"
date: 2026-05-31T19:00:00+03:00
deadline_reg_date: 2026-05-31T18:55:00+03:00
draft: false
featured_image: "/images/kv_list/2026-05-31/1.webp"
time: "19:00"
location: "Название Места"
price: "0"
address: "г. Нижний Новгород, ул. Пример, 1"
contacts: "+7 (910) 387-27-47"
duration: "3 часа"
description: "SEO-описание мероприятия"
yandex_maps_link: "https://yandex.ru/maps/..."
eventFormat: |
  - Правило 1
  - Правило 2
participants:
  - name: "Имя Фамилия"
    instrument: "вокал, гитара"
    songs:
      - "Исполнитель - Название"
# Фото галереи берутся автоматически из папки события — список ниже можно не заполнять
photos:
program:
  - time: "19:00"
    title: "Встреча гостей"
---
```

### Описание полей

| Поле | Обязательное | Описание |
|------|:---:|-----------|
| `title` | да | Заголовок страницы. Формат: `"Квартирник в {Место}"` |
| `date` | да | Дата и время начала. Формат: `YYYY-MM-DDThh:mm:00+03:00` (МСК) |
| `deadline_reg_date` | нет | Когда закрывается регистрация. Обычно за 5 минут до начала |
| `draft` | да | `true` — скрыт, `false` — опубликован |
| `featured_image` | да | Главное фото для шапки. Путь от корня сайта |
| `time` | да | Время начала для отображения (например `"19:00"`) |
| `location` | да | Название площадки |
| `price` | да | Цена входа. `"0"` = бесплатно |
| `address` | да | Полный адрес, начинается с `"г. Нижний Новгород, ..."` |
| `contacts` | да | Контактный телефон |
| `duration` | нет | Продолжительность (например `"3 часа"`) |
| `description` | да | SEO-описание для поисковиков и соцсетей (1-2 предложения) |
| `yandex_maps_link` | нет | Ссылка на Яндекс.Карты. Отображается в карточке места |
| `eventFormat` | нет | Markdown-список правил мероприятия |
| `participants` | нет | Список участников (см. ниже) |
| `photos` | нет | **Обычно не нужно.** Фото галереи подтягиваются автоматически из папки события. Заполняйте список вручную, только если нужна особая курация/порядок (см. ниже) |
| `program` | нет | Таймлайн программы (см. ниже) |

## Правила и соглашения

### Именование файлов
- Файл контента: `YYYY-MM-DD.md` (дата мероприятия)
- Папка фото: `static/images/kv_list/YYYY-MM-DD/`
- Фото нумеруются: `1.webp`, `2.webp`, `3.webp`, ...
- Превью: `static/images/kv_list/YYYY-MM-DD/thumbs/1.webp`, ...

### Галерея: фото подтягиваются автоматически 🆕
Достаточно положить фотографии в папку события — список в `photos:` вести **не нужно**.
- В галерею попадают все картинки из `static/images/kv_list/YYYY-MM-DD/` (форматы webp/avif/jpg/png).
- Порядок — по числу в имени: `1, 2, … 10, 11` (а также `m_1, m_2, …`).
- **Обложки игнорируются**: файлы с `title`, `banner`, `preview`, `cover`, `header`, `logo` в имени в галерею не попадают (используйте их для `featured_image`).
- Подпапка `thumbs/` пропускается; превью для каждой фотографии должно лежать там с тем же именем.
- Если в `.md` всё же задан список `photos:` — он имеет приоритет (ручная курация/порядок), авточтение отключается.

### Изображения
- Формат: **только WebP**
- Главное фото (`featured_image`): рекомендуемый размер 2560px по ширине
- Превью (thumbs): 480px по ширине
- Все фото с lazy loading — порядок не критичен, но `1.webp` используется как обложка

### Участники (participants)
```yaml
participants:
  - name: "Имя Фамилия"        # обязательно
    instrument: "вокал, гитара"  # необязательно
    songs:                       # необязательно
      - "Исполнитель - Название песни"
      - "Название (авторская)"
```
- На странице первые 3 участника показываются сразу, остальные — по кнопке "Показать ещё"
- Песни отображаются как теги под именем участника

### Программа (program)
```yaml
program:
  - time: "19:00"
    title: "Встреча гостей, знакомство"
  - time: "19:05"
    title: "Первый сет выступлений"
```
- Отображается как вертикальный таймлайн
- Время в формате `"HH:MM"`

### Фотографии (photos)
```yaml
photos:
  - "/images/kv_list/2025-10-05/1.webp"
  - "/images/kv_list/2025-10-05/2.webp"
```
- Первые 9 фото показываются сразу, остальные — по кнопке "Показать ещё"
- Клик по фото открывает модальный просмотрщик

### SEO-описание (description)
Формат: `"Квартирник в {Место} в Нижнем Новгороде. {Детали} — {дата прописью}"`

Пример:
> Квартирник в баре Хитрый Лис в Нижнем Новгороде. Живая музыка, 17 участников и камерная атмосфера акустического вечера — 5 октября 2025

### Регистрация
- Если `deadline_reg_date` указан и ещё не наступил — в меню появляется кнопка "Регистрация", а на главной — кнопка "Зарегистрироваться"
- Если поле не указано — регистрация считается открытой всегда
- Формат: `YYYY-MM-DDThh:mm:00+03:00`

### Draft-статус
- `draft: true` — страница видна только на dev-сервере (`hugo server -D`)
- `draft: false` — страница опубликована
- На главной отображается ближайший **будущий** эвент с `draft: false`

---

## Жизненный цикл эвента

1. **Анонс** — создайте эвент скриптом, заполните основные поля, установите `draft: false`
2. **Сбор участников** — добавляйте участников в `participants` по мере регистрации
3. **После мероприятия** — добавьте фото в папку и пропишите пути в `photos`
4. **Архив** — эвент автоматически попадает в архив после даты проведения
